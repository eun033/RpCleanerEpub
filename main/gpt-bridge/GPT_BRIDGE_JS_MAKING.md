# GPT 브리지 공용 UI 설계

GPT 브리지를 공급자로 추가하는 userscript와 웹 클라이언트가 함께 따르는 화면·상태·요청 기준이다. 제품별 색상과 문구는 바꿀 수 있지만, 연결 정보 보호와 pending 복구 규칙은 유지한다.

## 표시 조건

- 공급자 목록에는 `GPT 브리지 (ChatGPT 구독)`처럼 다른 API 공급자와 구분되는 이름을 사용한다.
- 연결 칩, pair 주소, 모델 확인, pending 작업 등 브리지 전용 설정은 GPT 브리지를 선택했을 때만 표시한다.
- 다른 공급자를 선택하면 브리지 영역 전체를 숨기고 해당 공급자의 기존 입력란을 복원한다.
- 브리지 전용 값과 `client` 메타데이터를 다른 공급자의 요청에 섞지 않는다.

## 권장 화면 순서

1. **연결 프로필 칩**: 저장된 연결만 표시하고 선택한 칩에는 체크를 붙인다. 빈 슬롯이 있으면 맨 앞에 `+` 칩을 표시한다.
2. **연결 이름**: `+`로 이름을 만든다. 기존 이름은 칩을 550ms 길게 눌러 변경하며 키보드 환경에서는 `F2`도 지원할 수 있다.
3. **브리지 연결 주소**: `http://127.0.0.1:포트/#pair=…` 전체 주소를 받는다. 비밀번호 입력처럼 가리고 OAuth 토큰은 받지 않는다.
4. **연결 작업**: `모델 확인`, `대기 요청 확인`, `대기 요청 폐기`를 제공한다.
5. **모델**: 선택한 연결의 `GET /api/models` 결과만 표시한다. 목록을 받기 전에는 임의의 모델명을 채우지 않는다.
6. **추론 강도**: 선택 모델이 제공하는 `efforts`만 표시하고 `default_effort`를 기본값으로 사용한다.
7. **선택 설정**: 방 이름처럼 GPT 입력에 추가되는 값은 별도 토글로 제공하고 기본값은 끈다. 이 설정도 GPT 브리지 선택 시에만 표시한다.
8. **상태 영역**: 모델 수, 플랫폼, pending 상태와 오류를 한 영역에 표시한다.

## 여러 연결

- 연결 주소, 표시 이름, 플랫폼, 모델 캐시와 pending 요청은 연결 슬롯별로 분리한다.
- 연결은 최대 5개를 권장한다. 제품 제약이 다르면 개수는 조정할 수 있다.
- 칩을 바꾸기 전에 현재 주소 입력을 저장하고, 새 연결의 모델과 pending 상태를 불러온다.
- 저장된 pair 주소는 다시 화면에 채우지 않는다. `저장됨 · 새 주소를 넣으면 교체`처럼 저장 여부만 알린다.
- `GET /api/status`의 `platform`으로 Android·Windows·macOS 또는 일반 연결 아이콘을 표시할 수 있다.
- 새 연결에서 사용할 수 없는 이전 모델을 자동 선택하지 않는다.

## 상태와 오류

- 연결 주소 없음·형식 오류: 조회와 요청을 막고 완전한 `127.0.0.1` 연결 주소가 필요하다고 안내한다.
- 모델 목록 없음: 모델 선택을 비활성화하고 모델 확인을 먼저 요청한다.
- pending 있음: 새 POST를 만들지 않고 저장된 request ID를 GET으로 조회한다.
- 완료 결과 미적용: 사용자가 결과를 적용하거나 명시적으로 폐기할 때까지 새 요청을 막는다.
- 대기 요청 폐기: 확인 대화상자를 거치며, 클라이언트의 로컬 pending 기록만 지우고 서버 결과는 삭제하지 않는다고 알린다.
- 요청 중 방·연결·모델·원문이 바뀜: 받은 결과를 현재 화면에 적용하지 않는다.
- 오류·거절·부분 응답·시간 초과: 다른 유료 공급자로 자동 전환하지 않는다.

## 요청과 복구

1. 클라이언트가 request ID와 방·원문·모델·작업 지문을 POST 전에 로컬에 저장한다.
2. 전송 성공 여부가 불확실하거나 화면이 새로고침되면 같은 ID를 GET으로 먼저 조회한다.
3. 같은 ID로 본문을 바꾸지 않는다. 본문이 달라졌다면 새 ID를 만든다.
4. `completed`이고 결과가 비어 있지 않을 때만 제품의 결과 검증기로 넘긴다.
5. 결과 적용이 끝난 뒤에만 로컬 pending 기록을 지운다.

세부 API 계약은 [GPT 브리지 클라이언트 계약](docs/GPT_BRIDGE_PROTOCOL.md)을 따른다.

## 선택형 client 메타데이터

브리지의 최근 작업 화면에 출처를 표시하려면 POST에 다음 객체를 선택적으로 넣는다.

```json
{
  "client": {
    "id": "고유한-클라이언트-id",
    "name": "클라이언트 표시 이름",
    "version": "클라이언트 버전",
    "room_id": "로컬 방 ID",
    "room_name": "표시할 방 이름",
    "task_kind": "작업 종류",
    "task_name": "표시할 작업명"
  }
}
```

`client`는 로컬 최근 작업 표시용이며 OpenAI Responses 본문에는 전달되지 않는다. GPT가 방 이름을 알아야 하는 기능은 별도 토글을 두고, 사용자가 켠 경우에만 방 이름을 `instructions` 또는 `input`에 포함한다.

### 등록된 클라이언트 고유 이름

| 클라이언트 | `client.id` | `client.name` |
|---|---|---|
| RP 곁 · Rux | `rp-rux` | `RP 곁` |
| Crack Muse Writer | `crack-muse-writer` | `Crack Muse Writer` |
| HAP-GPT | `wish-hap-gpt` | `Wish HAP-gpt` |

`client.id`는 영문 소문자와 하이픈으로 만든 영구 식별자이며 다른 클라이언트에서 재사용하지 않는다. `client.name`은 브리지 최근 작업에 표시되는 고유 이름이다. 기존 값을 변경하면 과거 작업과 새 작업의 출처가 달라 보이므로 마이그레이션 없이 바꾸지 않는다.

## 모바일·접근성

- 연결 칩 행은 좁은 화면에서 가로 스크롤을 허용한다.
- 길게 누르는 동안 손가락이 움직이면 이름 변경을 취소해 스크롤과 충돌하지 않게 한다.
- 모델과 추론 강도는 가능한 한 네이티브 `<select>`를 사용한다.
- 상태 영역에는 `role="status"`와 `aria-live="polite"`를 사용한다.
- 선택·성공·오류를 색만으로 표현하지 않고 체크, 문구, `disabled` 상태를 함께 사용한다.
- pair 주소와 OAuth 토큰을 DOM, 콘솔, 오류 문구 또는 진단 자료에 노출하지 않는다.

## 구현 확인 목록

- [ ] GPT 브리지를 선택한 경우에만 브리지 설정이 보인다.
- [ ] 연결별 주소·모델·pending 저장 키가 분리되어 있다.
- [ ] POST 전에 request ID와 요청 지문을 저장한다.
- [ ] 새 요청 전에 기존 pending을 GET으로 복구한다.
- [ ] 결과 적용 전에 방·연결·모델·원문을 다시 확인한다.
- [ ] pair와 OAuth 토큰이 화면·로그·저장소 문서에 노출되지 않는다.
- [ ] 다른 공급자의 payload에는 브리지 전용 필드가 추가되지 않는다.
- [ ] 모바일 연결 칩과 상태 문구를 실제 브라우저에서 확인한다.
